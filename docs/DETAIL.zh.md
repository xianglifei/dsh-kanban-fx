# 任务看板 · 详细说明

[README](../README.md) 讲「是什么、怎么用」；这一页是细节参考：界面、自动保存、标题规则、数据格式、
Host 接口和各条链路。版本以 [`package.json`](../package.json) 为准（当前 0.9.0）。

## 界面

点阵画布上四张浮起的圆角卡（每列一张），颜色全部走 `--dsw-alias-*` token，深浅色都成立。

### 顶栏

- **视图切换**（看板 / 列表）在标题右侧：两段轻标签，没有外框。当前项一层 7% 实色软填充
  （按顶栏底色混色，点阵不会从选中块里透出来）+ 600 字重，非当前项二级灰；窄到 360px 以下只剩图标。
  视图是页面级选择，只换内容区，默认看板，选过的记在浏览器本地。
- **工作区切换器**在右上角，不是筛选器：一次只显示一个工作区，没有「全部」，切换成本和在侧边栏切一样。
  进来时停在「上次看过的工作区」；从工作区的「…」菜单进来，就是点的那个。切换器前的「工作区」是字段名，
  12.5px、字重 560、二级文字色，比下拉里的值大半级。
- **设置齿轮**在最右侧（「+ 新建待办」右边），点进去只换内容区，返回后回到进入前的视图和工作区。
- 顶栏没有刷新按钮：数据新鲜度全自动，只有读取失败时错误条上出现「重试」。

### 侧边栏入口

每个工作区行尾「…」菜单的第一项是**「打开任务看板」**，排在「重命名」「在 Finder 中显示」前面：
点一下切到看板，并把工作区切换器落在**这个**工作区上，不用进去再切一次。工作区行右键弹出的也是同一项；
看板已经开着时点它只换工作区，不会重开页面。

### 新建待办

两个入口可以并行使用：

- **右上角**：面板工具栏最右侧的「+ 新建待办」；
- **内容末尾**：看板在待办列尾（下一张卡片会出现的位置），列表在表尾（排序后它只是入口，不再代表位置）。

窄屏（<700px）下右上角入口一直在；看板的待办列入口在切到待办状态时同样可用，列表的表尾入口一直在。
窄到 430px 以下，右上角的新建收成「+」，把宽度让给「看板 / 列表」两个标签。

「所属工作区」默认是当前工作区，必填。

如果设置里打开了「在卡片上提供独立工作树」，且 DSH 已启用工作树服务，表单里会多一个
**「在独立 worktree 中运行」**（默认不勾，没选工作区时禁用）：

（0.6.0 的界面图待补；现有设置页截图是 0.5.0 的，还没有「实验功能」卡。）

- 勾上只影响这张卡片**第一次执行**：建会话后先新建分支与检出、把会话目录切过去，再投递内容；之后重跑都在这份检出里。
  已经在项目目录真正跑过（投递过内容）的卡片不会被中途搬进新检出。
- 分支名形如 `fx-12-fix-login`（`fx-<编号>-<ASCII 标题片段>`，全中文标题就是 `fx-12`）；目录在仓库
  `.agents/worktrees/` 下，由 DSH 的工作树服务决定。
- 卡片执行过（真的投递过内容）之后不能再改这个选项；建会话 / 建工作树就失败的卡片仍可编辑重试。

### 卡片脚部：一行放不下时先缩、再收、最后换行

卡片脚部是一行：左边是状态类信息，右边是按钮。四列并排时一列只有一百多到三百多像素，而这一行里的每个文字块
都可能被 flex 压到它自己的最小宽度 —— CJK 的最小宽度是**一个字**，于是「运行中」「完成」「用时 3 分 20 秒」
都会被折成两行甚至竖排（0.6.0 及更早就是这样）。

0.6.1 起脚部里的文字一律不折行，按三级处理：能缩就缩，缩不了就收起次要信息，还放不下才整块换到下一行。

| 卡片 | 宽列 | 窄列（脚部 < 190px，或「开始于」< 230px） | 最窄 |
|---|---|---|---|
| 进行中 | `● 03:07 运行中` · `开始于 11/15 14:30` | 收起「开始于 …」（英文 < 260px 就收） | 英文状态词收成 `wrapping…`，不溢出卡片 |
| 进行中（等你回答） | `● 00:40 等你回答` · `开始于 11/15 14:30` | 同进行中；英文 `● 00:40 waiting` | 英文在 4 列并排的下限收成 `waitin…` |
| 待审核 | `用时 3 分 20 秒` · `✓ 完成` | `用时 3 分`（1 小时以上 → `1 小时`） | 按钮换到第二行，靠右 |
| 已完成 | `完成于 11/14 09:20` · `↩ 撤销` | `完成于 11/14` | 同上 |
| 归档卡（两个按钮） | 一行放下 | 放不下就把按钮整体挪到下一行 | 每个按钮一行，都靠右 |

「等你回答」的圆点是琥珀色、不闪 —— 它不是进度，是球在你这边；计时显示的是**已经等了多久**，
回答之后切回本轮的运行计时（等待时长不计入「用时」）。

判断用的是**这一列**的宽度，不是面板宽度：单列窄屏（<700px）列就是整屏宽，脚部照常显示完整文案。
阈值是拿真实字体量出来的宽度再加余量（「开始于」那条还把 `1:03:07` 这种跑过一小时的计时算进去），
所以文案缩短 / 收起之前不会先出现省略号或换行；`text-overflow: ellipsis` 只作最外层的兜底。
换行时卡片高约 30px，但没有任何一个词被拆开 —— 这比把「完成」拆成两行好读得多。

想看被收起来的开始时间：窗口拉宽到四列每列 ≈ 275px 以上（英文 ≈ 305px）它就回来了；
「用时」在每列 ≈ 235px 以上恢复成带秒的完整写法。

### 数据新鲜度

一次读取看板本身也会让 Host 做一次状态校准（把「进行中」但会话其实已经停了的卡片落回待审核），
所以手动点刷新与不点没有区别。新鲜度靠四层保证：

- **变化推送**：Host 每次改卡片都通过 SSE 推一个 `rev`，页面收到就静默重读，正常是秒级；
- **兜底轮询**：15 秒一次静默重读；
- **回到前台**：窗口重新获得焦点、或标签页重新可见时各读一次；
- **心跳**：Host 每 25 秒推一帧 `beat`，页面 70 秒收不到任何一帧就重建订阅并补读一次，
  防止连接半死（例如订阅超过 8 条被 429 拒掉）之后页面一直停在旧数据。

## 列表视图

![列表视图：平铺表格，默认按状态、流程顺序](../doc/界面%20-%202026-11-14/列表视图-浅色.png)

列表不按状态分组：状态只是每行一颗 pill（待办 / 进行中 / 待审核 / 已完成），表头 sticky，点任意可排序表头排序。
默认按状态升序 —— 流程顺序、待办在最上面；再点同一列反向。

| 列 | 内容 | 排序 |
|---|---|---|
| 状态 | 圆点 + 文案；待办中性、进行中 ink、等你回答琥珀、待审核琥珀、已完成绿 | 按 待办 → 进行中 → 待审核 → 已完成 |
| 编号 | `fx-12` | 按数字 |
| 任务 | 标题一行；附件数、有报错、会话已归档跟在后面 | 按标题 |
| 用时 | 进行中实时计时（等你回答时给已等时长）；待审核 / 已完成上一次用时；待办是 `—` | 按时长 |
| 更新 | 今天 / 昨天 / 月日 + 时刻 | 按时间 |
| 操作 | ▶ 执行 / ✓ 完成 / ↩ 撤销；归档卡片才有 ↻ 重新执行 | 不可排 |

- 未在排序的列显示淡的双向箭头，当前列只亮一边；`aria-sort` 同步，键盘可以直接 Tab 到表头按钮。
- 「更新」读卡片已有的 `updatedAt`（turn 开始 / 结束、编辑、完成都会更新），不新增字段。
- 视图和排序都记在浏览器本地（`dsh-kanban-fx.view` / `dsh-kanban-fx.sort`）；默认看板 + 状态升序。
- 平铺后没有组头计数，表尾补一行 `共 N 张 · 待办 … · 进行中 … · 待审核 … · 已完成 …`；
  有卡片在等你回答时写成 `进行中 2（1 张等你回答）`，窄屏表尾也补一句 `· 等你 1`。
- 已完成不再逐张折叠；按状态排序时它们自然在最后，想先看最近动过的就点「更新」。
- 表尾「＋ 新建待办」是第二条入口；排序后它不再代表「下一张卡的位置」，只是入口。
- 中等宽度（701–1080px）收起编号 / 用时 / 更新，只留状态 + 任务 + 操作；
  窄屏（<700px）只留任务 / 操作，状态变成标题前色点，进行中计时顶到操作列，表尾写明当前按哪列排序。

## 设置

![设置页：完成之后与高级](../doc/界面%20-%202026-11-14/设置页-浅色.png)

设置页只有一块会写服务端的内容，其余是只读诊断信息和本机界面偏好。

### 完成之后

| 选项 | 点「完成」之后 |
|---|---|
| 什么都不做（默认） | 立即移入已完成，和 0.4.0 完全一样；toast 带撤销 |
| 发送一条收尾提示词，跑完自动完成 | 先把提示词作为一条普通用户消息发进这张卡片的会话；卡片进入进行中并显示「收尾中」；这一轮**正常结束**才自动移入已完成 |

- 提示词最多 4000 字符，前后空白会去掉；选这个模式时必须非空。
- 报错 / 被中止：卡片回到待审核，不会标成已完成。
- 会话已归档 / 找不到：不再尝试投递，直接完成并提示「收尾提示词未发送」。
- 只对点击后的下一轮生效。收尾期间又去会话里补话，自动完成会落在下一轮 `turn/end`（已知限制，v1 不区分哪条是收尾消息）。
- 「收尾中」不是第五种状态：它仍在进行中列，排序 / 筛选 / 计数都按进行中算，只是卡片脚部、列表状态和会话标题栏显示「收尾中」。
- 三个入口仍然都是「完成 = 回看板」：看板 / 列表直接换列；会话标题栏照旧跳回看板，只是落点是进行中（收尾中），
  提示改成「已发送收尾提示词，跑完自动完成」，且不提供撤销——消息已经发出去了。报错后卡片回待审核，可以再点一次完成重试。
- 撤销完成只撤销完成状态，不会撤回已经发出的消息。

设置停手 **600ms** 自动保存，页脚另有「保存」；保存走 `POST /kanban-fx/settings`，立刻生效，不重启插件、不断 SSE。
提示词明文存在本机 `board.json`，不要放密钥。

### 实验功能

只放一件事：**「在卡片上提供『独立工作树』」**（默认关闭）。它只是**入口开关**——决定卡片表单里要不要出现那个
复选框，不等于「允许使用工作树」。能力本身由 DSH 的插件决定：

- 服务不可用（插件页没启用工作树套件）：复选框禁用，下方显示「服务未启用」并指路
  「设置 → 插件 → 变更请求与工作树」；卡片表单不出现复选框，执行时也不会建。
- 服务可用、开关打开：卡片表单出现复选框，卡片默认仍不勾。
- 关掉开关不会搬走已有的卡片：已经建好的 worktree 在再次执行时仍然沿用，新建才会停下。
- 开关即时保存（`POST /kanban-fx/settings` 只发 `worktree` 这一段，服务端按当前值合并），失败在原位提示，不静默丢改动。
- 高级区多一行只读的「工作树服务：可用 / 未启用」，方便排障。

### 高级

数据 / 限制 / 关于只读；界面偏好只写本机 localStorage：

- 数据：数据目录、`board.json` 路径（可复制）、存储版本、卡片总数；
- 限制：单张卡片正文字符上限、附件总大小上限（在 `cordis.patch.yml` 里改，重启生效）；
- 关于：插件版本、数据格式版本、接口前缀；
- 界面偏好（本机）：当前视图 / 列表排序，以及「恢复视图与排序默认值」——只清浏览器本地的两个 key，不动工作区记忆和卡片数据。

设置存进 `board.json` 而**不是** `cordis.patch.yml`：改配置会让插件重启，而这是一项应该即时生效的用户设置；
部署级的目录 / 上限仍留在 `cordis.patch.yml`。

## 自动保存

新建 / 编辑待办的侧栏默认开着自动保存，不用记着点「保存」：

| 时机 | 行为 |
|---|---|
| 停手 1.2 秒 | 把当前内容存一次（第一次会自动把草稿落成待办卡片） |
| 一直打字 | 每 8 秒兜底存一次 |
| 点侧栏外面 / 按 Esc / 点 ✕ | 关闭前再补存一次 |
| 点「保存」 | 立刻落库并关闭 |
| 点「▶ 立即执行」 | 先落库，再开跑 |

- 第一次自动保存后就固定在同一张卡片上更新，不会越写越多张。
- 附件只在第一次上传，后续保存只带引用，不会每 8 秒重传一遍。
- 补存失败（比如网络抖动）会留在侧栏里报错，不关闭、不丢内容；恢复后再关一次就存上了。
- 如果这张卡片在 Host 侧真的没了（被删掉 / 数据被换过），下一次自动保存会自动新建一张兜底，不会一直报「卡片不存在」。
- 侧栏底部一直显示状态：`自动保存已开启` / `有改动，稍后自动保存` / `自动保存中…` / `已自动保存 21:13`。

## 标题与首条消息

卡片标题可以留空。两种写法在执行时走不同的规则：

| 你写的 | 卡片标题 / 会话名 | 首条消息 |
|---|---|---|
| 手写标题 + 正文 | 手写标题 | `# 手写标题` + 空行 + 正文原样 |
| 手写标题，正文空 | 手写标题 | 标题本身（不加 `#`） |
| 标题留空 + 正文 | 正文第一个非空行（剥掉行首 `#` / 列表 / 引用记号，按句读或空格边界截到 42 字） | 正文原样，不加标题行 |
| 标题留空，只有附件 | 附件名（只有一个附件时；多个则「未命名事项」） | 只有附件 |
| 手写标题与正文首行是同一句 | 手写标题 | 正文原样（不重复发标题） |

- 只有**你亲手写的标题**会进消息；自动派生出来的标题只做卡片标题和会话名，不会在消息里再出现一遍，
  所以正文不会被重复发送。
- 新建 / 编辑侧栏里，派生标题不回填到标题框：标题框留空并显示「标题未填写」，下面实时预览「会话名：……」；
  想换个名字直接写，写了就以你写的为准（清空又回到自动派生）。
- 旧数据（v1）里 `title` 等于老派生结果的卡片，加载时会认成「当年没手写」，迁成空串继续自动派生；
  其余保留为手写标题。

## 卡片编号

每张卡片落库时会拿到一个短编号，对用户显示为 `fx-1`、`fx-2`……（数据里只存数字 `seq`，`fx-` 是显示前缀）。

- 出现在**新建 / 编辑待办的侧栏标题旁**（灰色小字）和**列表的「编号」列**；看板卡片上不显示；
- 草稿在第一次自动保存（或点「保存」）后才拿到编号，拿到后标题旁会即时出现；
- 点一下编号即可复制，以后在会话里可以直接说「处理 fx-12」；
- **只增不复用**：删掉 `fx-3` 之后，下一张新卡仍是 `fx-4`，空号不会回收；
- 旧数据第一次加载时按创建时间补号（1、2、3……），之后保持不变；编号存在 `board.json` 里，重启不重排。

## 数据

- 看板数据：`$DSH_HOME/dsh-kanban-fx/board.json`（默认 `~/.dsh/dsh-kanban-fx/board.json`）。
  卸载插件后数据仍留在磁盘上。
- 存储版本 `version: 2`：`title` 从 v2 起只存**用户手写的标题**（空串 = 自动取正文首行）；
  加载 v1 数据时会按老派生规则把自动标题迁成空串。看板接口里的卡片另外带 `titleInput`（手写原文）与
  `titleDerived`（是否自动），`title` 是 Host 实时派生的展示标题。
- 用户设置：`settings.completion = { mode: 'none' | 'prompt', prompt: string }`，默认 `none`；
  `prompt` 最多 4000 字符，明文存在 `board.json`。这是**可选新增字段**，旧文件没有就按默认读，
  所以存储版本仍保持 2，不触发标题迁移。
- 收尾标记：卡片上的 `finishingSince` 是收尾轮开始时间，非空即「收尾中」；`turn/end` 正常结束才写 `doneAt`。
- 等待标记：`awaitingSince`（等用户回答的起点）+ `awaitingKind` / `awaitingId`（`question` 认 tool call id，
  `approval` 认审批 id）+ `awaitingMs`（累计等待时长，用来从「用时」里扣掉）。**只活在内存里**：
  `loadStore` 一律清空，重启后那次提问已经不在，标记留着只会让卡片永远「等你回答」。
  接口里带 `awaiting` / `awaitingSince`，Client 据此换文案、排序和计时。
- 接口里的 `advanced`（版本、数据目录、上限）是只读运行信息，不落库；本机界面偏好仍只存 localStorage。
- 卡片编号：卡片上有 `seq`（数字），看板文件顶层有 `nextSeq`（下一个可用号），两者一起保证编号不重号、不复用。
- 列表的「更新」列读卡片已有的 `updatedAt`（turn 开始 / 结束、编辑、完成都会更新），不新增存储字段。
- 附件：走 DSH 自己的附件服务（和新建会话输入框同一套落盘），卡片里只存引用。
- 单张卡片附件总量上限 24 MB，单张卡片正文上限 20 万字符（可在 `cordis.patch.yml` 里改）。

## Host 接口

所有接口都在 `/kanban-fx` 前缀下，非 `/api` 路由，插件自己做了 DSH 的 Host/Origin 与登录校验。

| 方法与路径 | 用途 |
|---|---|
| `GET /kanban-fx/board` | 看板快照（卡片、工作区、默认工作区 = 校验过的 `lastWorkspaceId`、`rev`、`serverNow`，以及 `settings` / `advanced`；卡片带 `worktree` / `preparing` / `awaiting` / `awaitingSince`，`advanced.capabilities.worktrees` 是服务探测结果） |
| `GET /kanban-fx/events` | SSE：有变化推 `rev`（25 秒没变化也会推 `beat` 心跳）；客户端收到 `rev` 后自己重读 `/board` |
| `GET /kanban-fx/attachment?id=` | 卡片附件的原图 / 原文件 |
| `GET /kanban-fx/card?sessionId=` | 会话对应的卡片（给会话页标题栏用）；不是看板卡片返回 `card: null`；卡片附带 `completionMode` 供 tooltip 用 |
| `POST /kanban-fx/card` | `{action: create \| update \| delete \| run \| done \| undone, ...}`；`done` 传 `id` 或 `sessionId` 都可以 |
| `POST /kanban-fx/settings` | `{settings:{completion?:{mode:'none'\|'prompt', prompt}, worktree?:{offer:boolean}}}`；两段各自可缺省，按当前值合并后严格校验，返回完整看板载荷 |

完成接口的 `done` 响应多两个字段：`completionResult`（`done` / `sent` / `fallback-done`）和
`completionWarning`（`session-archived` / `session-missing`，仅 fallback）。`sent` 表示卡片现在在收尾中。

## 执行链路

1. `ctx.sessionController.create({ sessionId, workspaceId })` 建会话（自动挂到该工作区，出现在侧边栏）。
2. 会话标题改成卡片的展示标题（手写标题优先，没写就取正文首行），所以侧边栏看到的是你的任务名。
3. 首条消息的文本：手写标题作 `# 标题` 第一行 + 空行 + 正文原样（正文首行已经是同一句时省略标题行，
   没写标题时只发正文）；图片/文件 → `ctx.attachments.saveImage/saveFile` 的引用 → 原生 `image`/`file` 块。
4. 卡片勾了工作树（且全局入口开着、服务可用）时，先把内容拼好，再调
   `ctx.worktrees.create(agent, { name })`：DSH 新建分支与检出、`workingDirectory.set` 切目录、写
   `plugin:worktree/created` 事件；看板记下返回的 `path / branch / baseCommit / repositoryRoot`。
   建树期间卡片 `preparingSince` 非空（状态仍是进行中，显示「准备工作树」），`reconcile` 不猜它结束；
   失败则清标记、把中文原因写进 `card.worktree.error`、卡片回待办，重试换一个带随机后缀的分支名（只重试一次）。
5. `agent.followup({ id, role:'user', content, source:{kind:'user'} })` 立刻开跑。
6. 监听 `session/event` 的 `turn/start` / `turn/end` 维护状态与计时。

### 等你回答（不是第五种状态）

`ask_user_question` 会把这次 tool call **挂起**等回答，答案作为它的结果回来；权限确认同理走 `approval/asked`
与 `approval/decided` 这对审计事件。这段时间里 agent 的 status 仍是 `running`，`turn/end` 也不会来 ——
所以卡片照旧留在**进行中**，插件只额外记一个派生标记：

1. `tool/call` 且 `name === 'ask_user_question'` → 记 `awaitingSince` / `awaitingKind = question` / `awaitingId = callId`；
2. 同一个 `callId` 的 `tool/result` → 清标记，等过的时长累加进 `awaitingMs`；
3. `approval/asked` / `approval/decided` 用审批 id 走同一套；
4. `turn/start` 清掉整组（新的一轮），`turn/end` 与 `reconcile` 兜底清掉并结算等待时长；
5. 这一轮的 `lastRunMs` = 结束时间 − 开始时间 − `awaitingMs`，即「等你想 / 等你点」的时间不算任务用时。

`statusOf` 不看 `awaiting`：它只是进行中的一种文案。看板把它排到进行中列最前、列头计数变琥珀色，
列表 pill 写「等你回答」，会话标题栏的状态标写「等你回答」而不是「进行中」。

## 完成链路

1. 看板 / 列表 / 会话标题栏点完成 → `POST /kanban-fx/card {action:'done'}`。
2. mode = none：`doneAt = now`，返回 `completionResult: 'done'`。
3. mode = prompt：校验 review → `resolveAgent` → 写 `runningSince` / `finishingSince` →
   `agent.followup({ id, role:'user', content:[{type:'text', text: prompt}], source:{kind:'user'} })`；
   返回 `'sent'`。会话已归档 / 找不到 → 直接 `doneAt`，返回 `'fallback-done'` + warning。
4. `turn/end` 正常 → `doneAt = event.time`，清 finishing；`error` / `aborted` → 清 finishing，留在待审核。
5. `reconcile` 每 30 秒兜底：收尾中超过 10 秒且 agent 不在 running → 回待审核并提示重试；
   Host 重启后同样不猜成功。

## 在会话页标记完成

从看板或列表「执行」出来的会话，标题栏（会话标题右边）会多出两样东西（勾了独立工作树时再多一枚分支标）；普通新建的会话没有：

- **卡片状态**：`● 进行中` / `● 收尾中` / `● 等你回答` / `● 待审核` / `● 已完成`，颜色和看板列头那颗点一致；
  「收尾中」用的是进行中的 ink，「等你回答」用待审核的琥珀色，只是文案不同。这一轮在跑时标题栏每 4 秒问一次 `GET /card`，
  问句一出现就在 4 秒内换成「等你回答」，回答后同样回到「进行中」；
- **「✓ 完成」按钮**：只在待审核出现。普通模式下点一下把卡片标成已完成，并直接切回任务看板，
  任务看板会切到这张卡片所在的工作区，落地后弹一条「已把 fx-12 移到已完成 / 撤销」。
  prompt 模式下仍然切回看板，但卡片落在进行中（收尾中），提示改成「已发送收尾提示词，跑完自动完成」，
  不提供撤销（消息已经发出去了）。
  这条分支上还有没合并的提交时（见下一节），第一次点不会标完成，按钮就地变成「未合并，仍要完成？」
  （琥珀色），6 秒内再点一次才标；超时 / 这一轮结束都会收回成「✓ 完成」。
- **工作树位置**（只有勾了独立工作树的卡片才有）：状态标左边一枚分支标 = 分支图标 + 等宽字体分支名，
  排在「预设标签（Standard）」和状态标之间。会话跑在 `.agents/worktrees/` 的检出里，项目目录看不到这些改动，
  标题栏不写出来就会「在会话里改完、跑完直接归档」，以为已经合进项目目录。悬停给出：
  首句（在跑 / 已结束两种）、`分支：fx-12-…`、`目录：/…/.agents/worktrees/fx-12-…`，以及
  「合并回主分支（在项目目录 `git merge fx-12-…`）；归档会话时 DSH 会删掉检出，分支保留」。
  勾了但第一次执行还没建好时是虚线的「准备工作树」（透明底、降一档文字色）；建树失败时只剩红字「工作树失败」，
  原因在 tooltip，不会一直挂着「准备工作树」；没勾就没有这一枚。

约定是「圆点 = 状态，✓ = 动作」，所以进行中、收尾中和已完成不显示按钮。状态完全跟着会话走：

| 会话里发生了什么 | 标题栏 |
|---|---|
| 这一轮还在跑 | `● 进行中`，没有按钮 |
| 收尾提示词在跑 | `● 收尾中`，没有按钮 |
| 助手问你一句 / 等权限确认 | `● 等你回答`，没有按钮；回答后回 `● 进行中` |
| 这一轮跑完 | `● 待审核`，出现「✓ 完成」 |
| 收尾轮正常结束 | `● 已完成`，没有按钮 |
| 收尾轮报错 / 中止 | `● 待审核`，出现「✓ 完成」；报错时卡片带「有报错」 |
| 待审核时继续说话 | 当场回到 `● 进行中`，按钮消失；跑完再回待审核 |
| 点过完成之后再进来 | `● 已完成`，没有按钮 |
| 普通会话 / 卡片已删 / 会话已归档 | 什么都不显示 |

## 已完成列的分支合并状态

卡片在独立工作树里干完活之后，「改在哪条分支上」和「合进主分支没有」是两件事。看板只观测后者，
而且只在**已完成**里说：待审核的「未合并」是常态，标成琥珀只会训练人忽略它；提醒放在点「完成」的那一刻。

| 折叠行 / chip | 含义（Git 事实） | 你接下来要做什么 |
|---|---|---|
| `未合并`（琥珀） | 分支在，有提交，没被任何本地 / 远端分支包含 | 合并，或决定丢弃 |
| `已合并`（绿） | 分支 tip 已被主分支（或别的分支）包含 | 可以删分支（可选） |
| `已合并，已删`（灰） | 曾经观测到已合并，现在分支没了 | 什么都不用做 |
| `无改动`（灰） | 分支 tip 就是建树时的提交，没有提交，检出也干净 | 可以删分支（可选） |
| `未提交`（琥珀） | 分支上没有提交，但检出里还有没提交的文件 | 让会话提交，或自己提交；合并带不过去 |
| `未合并，已删`（红） | 曾经观测到未合并，现在分支没了 | 改动可能丢了：reflog / Forge / PR 里找 |
| `已删除，待确认`（灰） | 第一次看到时分支就已经不在了 | 无从判断；分支名不在提交里，删了不能倒推 |

- **折叠行给结论，展开卡给细节**：已完成默认折成一行标题，所以结论挂在折叠行右侧（只有状态词）；
  展开后是完整分支标（分支图标 + 分支名 + 状态），删掉的分支带删除线，悬停给出分支、提交数、
  并进哪个分支、`git merge` 命令和「记录于 …」。列头在有未合并时补一枚琥珀 `2 未合并`
  （含「未合并，已删」），点开列里能看到红色那张。
- **只读 Git 观测**：每仓库最多 60 秒问一次 `git for-each-ref refs/heads refs/remotes`；
  分支还在时对 tip 问 `--contains`，并用 `rev-list --count <baseCommit>..<tip>` 数提交，
  再在检出里跑一次 `git status --porcelain` 看有没有未提交的文件（`dirty` / `dirtyCount`）。
  不 fetch、不写仓库、不带 shell、3 秒超时、64KB 截断、`GIT_OPTIONAL_LOCKS=0` 不碰 index；
  Git 不可用 / 仓库不在了只清掉这次观测，卡片退回普通分支标，看板照常返回。观测结果存在
  `card.worktree.merge`（`state` / `gone` / `into` / `ahead` / `dirty` / `dirtyCount` / `observedAt` /
  `goneAt`），只在状态真的变了才落盘、才推 rev。
- **为什么必须落盘**：分支被删之后，提交里没有分支名，没法倒推「它合没合并」。所以只有先前观测到过，
  才能说「合并后已删」。这也是历史卡片（比如分支早就删掉的那两张）只能显示「已删除，待确认」的原因。
- **不 fetch**：远端合并要先在本地 `git fetch` 过，才能从 `origin/main` 里看到包含关系。
- **squash / rebase 认不出来**：分支 tip 不在目标分支里，会显示「未合并」。所以文案不写死「没合」，
  tooltip 里明说这一点；红色只在「删分支之前确实观测到未合并」时才亮。
- **开关**：设置 →「实验功能」→「在已完成列标出分支合并状态」（默认开，存 `settings.worktree.mergeState`）。
  关掉后卡片只显示分支名、点完成也不再提醒，Host 也不再探测；已经存下的观测保留，重新打开立刻可用。
- **点完成前拦一下**：命中「未合并 / 未提交」时，看板 / 列表弹一张小卡，
  标题跟着真实原因（「这个分支还没合并」/「检出里还有未提交的改动」/两者都有），里面给三条路：
  「让会话合并」（默认焦点，见下）、「复制命令」、「先去合并」（关掉，自己来），以及「仍然完成」。
  会话标题栏则把「✓ 完成」就地变成「未合并，仍要完成？」或「有未提交改动，仍要完成？」，再点一次才标。
  开关关掉、或卡片没有 worktree 时不拦。
- **复制命令**：分支标末尾那枚小按钮（未合并给合并命令，已合并 / 无提交给清理命令），确认卡里也有「复制命令」。
  复制的是带前置说明的两行：
  `# 在项目目录的目标分支上执行（先确认 git status 干净）` + `git -C <repo> merge --no-ff <branch>`；
  清理是 `# 归档会话会让 DSH 清掉检出；也可以手动移除，然后删分支` + `git -C <repo> worktree remove <检出>` +
  `git -C <repo> branch -d <branch>`。只写剪贴板，不动仓库。
- **让会话合并**：`POST /kanban-fx/card {action:'merge'}` 给这张卡片的会话发一条消息，内容包含仓库根、分支、
  检出和步骤（切到目标分支 → 有未提交改动先提交 → `git merge --no-ff` → 跑测试 → 移除检出 → `git branch -d`
  → 报告结果；冲突就停下来）。插件自己不跑写操作的 Git，Git 由模型在会话的沙箱与权限下执行。发出去等于
  重开一轮：卡片回到进行中，`turn/end` 再落回待审核。护栏：这一轮还在跑 409、没有工作树 400、
  会话已归档 / 找不到 409、没有会话服务 503。已完成卡片展开后脚部也有「合并」按钮（会话不在时不显示）。
- 设置里工作树开关下面还有一行提醒：「点『完成』时如果这条分支还没合并，会先提醒你一次……」，
  并说明关掉「合并状态」就不提醒——提醒依赖下文那个开关。
- 列表视图用同一枚分支标，不新增列；状态不参与排序、不占列、不放圆点。
- 挤窄时的取舍（都是容器查询，不看整个面板宽度）：折叠行先只留图标（tooltip 还在），更窄时整枚收起；
  列头那句「N 未合并」也在更窄时隐藏，只留数字。已完成的标题会比以前短一点——状态词优先。

## 会话被归档 / 删掉

- 卡片 / 列表行上会出现「会话已归档」徽标，点卡片只给提示，不再跳转。
- 卡片上会多一个「▶ 重新执行」，列表行尾部会多一个 ↻：它们会在同一个工作区开一个新会话重跑（旧会话保持原样）。
- 这一步是自动兜底：每次读取看板时都会核对归档集合。
- prompt 模式下对已归档 / 找不到的会话点完成：不再尝试投递，直接标完成并提示「收尾提示词未发送」，不会 500。

## 明确不做

拖拽排序 / 跨列手动移动 / 自定义列、在看板或列表里直接对话、子任务与截止日期、附件在线预览、
卡片多会话历史（会话页只多了标题栏的完成按钮，其余不做改造）。
列表这版也不做：列宽自定义、多选、搜索、「隐藏已完成」开关（靠状态排序把已完成压到底部）、
新建后的自动滚动定位；「全部工作区」仍不在范围内。
设置页也不做：每张卡片 / 每个工作区单独的收尾词、提示词模板变量、提示词库、完成后自动归档 / 通知、
导出 / 导入 / 清空看板、修改数据目录或正文字符 / 附件上限。
工作树也不做：自研 git 命令、基准分支选择、从卡片删除 / 恢复 / 锁定检出、每工作区默认值、按仓库记忆、
批量开启、卡片删除时清理分支（归 DSH 的归档清理与 Forge 面板）。

## 升级注意

任务看板分 Host（`index.js`，负责设置 / 存储 / 状态机）和 Client（`client.js`，负责页面）两半。
从 0.4.x 升到 0.5.0 后，刷新页面只会换 Client；运行中的 Host 仍是旧代码，点保存会得到「接口不存在」。
在 DSH 里把「任务看板」插件禁用再启用（或重启 DSH）才会加载新的 Host；看板数据不受影响。
重载可能刷新面板，保存前先把设置页里的草稿复制出来，重载后粘贴回去再保存。

0.5.1 只改 Client 的视图切换样式，刷新页面即可，不需要重载 Host。

0.6.0 加了卡片级工作树：Host 新增能力探测与执行前置，Client 新增设置项 / 编辑器选项 / 卡片 chip，两半都要更新
（重载插件或重启 DSH + 刷新页面）。启用功能还需要在插件页启用 DSH 的**「变更请求与工作树」**套件并重启；
没启用时功能只是灰着，不会影响原有卡片。`board.json` 只新增可选字段（`settings.worktree`、
`card.worktree`、`preparingSince`），不升存储版本。

0.6.1 只改 Client 的卡片脚部布局（进行中列不再折行），刷新页面即可，不需要重载 Host。

0.7.0 加了「等你回答」：Host 听 `ask_user_question` / 审批事件并维护派生标记，Client 换脚部文案、排到列首、
列头与列表 / 标题栏配色，两半都要更新（重载插件或重启 DSH + 刷新页面）。没有新增存储字段
（`awaiting*` 只在内存里），`STORE_VERSION` 仍是 2。

0.7.1 只在会话标题栏加了一枚工作树分支标，纯 Client；`GET /card` 早就有 `worktree.branch` / `worktree.path`，
Host、接口和 `board.json` 都没动。刷新页面即可，不用重启 DSH。

0.8.0 加了已完成列的合并状态：Host 新增只读 Git 探测与 `card.worktree.merge` 快照，Client 新增折叠行结论、
列头计数、点完成确认与设置开关，两半都要更新（重载插件或重启 DSH + 刷新页面）。`GET /board` 的卡片多出
`worktree.merge` 与 `worktree.probe`，`GET /card` 多出 `mergeState`，`POST /settings` 的 `worktree` 段接受
`mergeState`（只发一段时另一段保留）。`board.json` 只新增可选字段，`STORE_VERSION` 仍是 2。

0.9.0 在 0.8.0 的基础上补了三件事：检出未提交改动的只读探测（`merge.dirty` / `merge.dirtyCount`，多跑一条
`git status --porcelain`）、复制合并 / 清理命令、以及 `POST /card {action:'merge'}` 的「让会话合并」。Host 与 Client
都变了，禁用再启用插件（或重启 DSH）后刷新页面；`board.json` 只新增可选字段，`STORE_VERSION` 仍是 2。
「让会话合并」由模型执行 Git，权限与沙箱沿用那一轮的会话；会话只读、绑在别的工作区、或已经被归档时会明确拒绝。
