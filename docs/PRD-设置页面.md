## 0. 一句话与结论

**一句话**：加一个设置页，第一版只放一件事——决定点「完成」之后是**立即完成**，还是**先给这张卡片的会话发一条自定义收尾提示词，等这一轮正常跑完再自动移入已完成**。默认立即完成，和现在完全一样。

**结论**：方向成立，和现有「状态跟着会话走」的产品逻辑一致。它把「完成」从一个单点动作，变成一段可配置的收尾流程；默认关闭保证低风险。真正需要设计的是三件事：

1. **收尾期间要看得见**：卡片仍在「进行中」列，但状态显示「收尾中」，否则用户会以为任务还在干正事。
2. **失败不能自动完成**：收尾轮报错 / 被中止，必须回到待审核，而不是把失败悄悄标成已完成。
3. **「完成」的语义仍是「我审完了」**：看板 / 列表本来就在看板上，直接换列；会话标题栏照旧跳回看板。prompt 模式变化的是落点——卡片先进「进行中（收尾中）」，提示从「已移入已完成」改成「已发送收尾提示词，跑完自动完成」。不能让人以为点了完成却什么都没发生，也不能谎报已完成。

## 1. 背景与问题

### 1.1 现状

- 「完成」只有一种语义：用户在**待审核**卡片上手动点击，卡片立刻进入**已完成**；可以撤销。
- 用户想继续让 agent 做事，只能点开卡片进会话，手打一句话，等它跑完，再回看板点「完成」。
- 任务真正结束前，常常还有一句固定的收尾：写 CHANGELOG、提交代码、总结这轮改了什么、关掉 dev server、清理临时文件。

### 1.2 问题

- 这句收尾是**重复劳动**：每次都要切会话、重打一遍（或从别处复制）。
- 容易**忘**：跑完看到结果满意，直接点完成，收尾就漏了。
- 现有的「在会话里继续说话 → 进行中 → 跑完回待审核」不支持「这句话说完就结束」的表达。

### 1.3 用户故事

- 作为把任务拆成卡片的用户，我希望任务跑完后顺手把 CHANGELOG 写好，而不是切回会话再打一遍。
- 作为不想自动化的用户，我希望默认行为和现在一模一样，不要多一步确认。
- 作为要查历史的人，我希望收尾内容留在会话里，以后能翻到，而不是一次性的隐藏动作。
- 作为在会话页的用户，我希望点「完成」前就知道会不会触发收尾。

## 2. 目标与非目标

### 2.1 目标

- 增加一个**设置页**，承载用户级设置，并为后续高级项留位置。
- 第一项设置：「点『完成』之后做什么」，两个选项：
  - **什么都不做**（默认）：立即完成，行为与 0.4.0 一致。
  - **发送一条收尾提示词**：先把用户写的提示词作为一条普通用户消息发进当前会话，卡片进入「进行中（收尾）」；这一轮正常结束 → 自动进入「已完成」。
- 让收尾过程可见、可解释、可撤销（撤销的是完成状态，不是已发出的消息）。
- 不改动插件安装配置：改完设置立即生效，不重启插件、不断 SSE。

### 2.2 非目标

- 不做第五列「收尾中」；四列结构不动，只在「进行中」列里把状态文案显示成「收尾中」。
- 不做每张卡片、每个工作区单独配置收尾词（本期全局一条）。
- 不做多条提示词、提示词库、模板变量（`{{seq}}` / `{{title}}`）——见第 12 节。
- 不在设置页做危险操作：清空看板、导出 / 导入、删除卡片、改数据目录、改上限。
- 不改变现有规则：已完成 / 待审核的会话里继续说话，仍然回到进行中，跑完回待审核。
- 不做每次点击完成时的二次确认弹窗（会变成噪音）；只做一次性说明 + 持续可见的状态。
- 不把收尾消息伪装成系统消息：它就是一条普通用户消息，和用户手打的一样。

## 3. 术语

| 术语 | 含义 |
|---|---|
| 收尾提示词 | 用户在设置页写的一段文字；点「完成」时作为一条普通用户消息发进卡片会话 |
| 收尾轮 | 由收尾提示词触发的那一轮 turn |
| 收尾中 | 收尾轮正在跑；卡片仍算「进行中」，但状态文案显示「收尾中」 |
| 一次性 | 只对「点击完成后的下一轮」生效；自动完成后，用户再在会话里说话，仍按现有规则走 |

## 4. 方案总览

```
用户点 ✓ 完成
   │
   ├─ mode = none ───────────────────────► doneAt = now ──────────► 已完成（可撤销）
   │
   └─ mode = prompt
        │
        ├─ 会话已归档 / 找不到 ───────────► doneAt = now ──────────► 已完成 + 警告
        │
        └─ 投递收尾提示词
             │
             ├─ 这一轮正常结束 ───────────► doneAt = 结束时间 ────► 已完成
             ├─ 这一轮报错 ───────────────► 待审核（有报错徽标）
             └─ 这一轮被中止 ─────────────► 待审核
```

要点：

1. **先发消息，后完成**：不能先标 doneAt 再发，否则自动完成会误判。
2. **收尾轮正常结束才自动完成**：`turn/end` 的 reason 是 `error` / `aborted` 时一律回待审核。
3. **投递失败分两种**：会话没了 → 直接完成并提示（用户的完成意图优先）；agent 忙 / 解析失败 → 409，卡片不动，让用户重试。
4. **只有下一轮**：自动完成后 `finishingSince` 已清空；用户再说话按现有规则回进行中，跑完回待审核。

## 5. 交互需求

### 5.1 入口与页面结构

- 看板 / 列表顶栏最右侧新增一个**齿轮按钮**（在「+ 新建待办」右边），`aria-label="设置"`，窄屏只留图标。
- 点击后**内容区**切成设置页，不是抽屉、不是弹窗：
  - 顶部变成 `← 返回` + 「设置」两段，不再显示视图切换、工作区切换器、新建待办；
  - 返回后回到进入前的视图（看板 / 列表），视图 / 排序 / 工作区选择都不变。
- 设置页**不写进 localStorage**：刷新后回到看板 / 列表，不回到设置页。
- 内容宽度最大 760px 居中，和宽看板拉开；两段浮起圆角卡：
  1. **完成之后**（唯一可编辑的设置）
  2. **高级**（只读运行信息 + 本地界面偏好）
- 设置页打开时把焦点放到页面标题（`tabindex="-1"`），返回后焦点回到齿轮按钮。

```
┌ 任务看板 ────────────────────────────────┐
│  ← 设置                                  │
├──────────────────────────────────────────┤
│  ┌ 完成之后 ───────────────────────────┐ │
│  │ 点「完成」之后：                    │ │
│  │ (•) 什么都不做（默认）              │ │
│  │ ( ) 发送一条收尾提示词，跑完自动完成│ │
│  │   ┌──────────────────────────────┐  │ │
│  │   │ 把这轮改动补进 CHANGELOG.md… │  │ │
```

### 5.2 「完成之后」设置项

| 项 | 值 |
|---|---|
| 作用范围 | 整个看板，所有工作区共用一条 |
| 默认 | 什么都不做 |
| 选项一 | 什么都不做（默认） |
| 选项二 | 发送一条收尾提示词，跑完自动完成 |
| 提示词 | 多行文本；保留换行；首尾空白由 Host 去掉；上限 4000 字符 |
| 存储 | 服务端设置（`board.json`），所有浏览器 / 标签页共享 |

**文案（中文 / 英文）**：

| 位置 | 中文 | English |
|---|---|---|
| 区块标题 | 完成之后 | After marking done |
| 说明 | 设置点「完成」之后发生什么。对整个看板生效。 | Choose what happens after you mark a card done. Applies to the whole board. |
| 选项一 | 什么都不做（默认） | Do nothing (default) |
| 选项一说明 | 点「完成」立即移入已完成，和现在一样。 | Marking done moves the card to Done immediately, as before. |
| 选项二 | 发送一条收尾提示词，跑完自动完成 | Send a wrap-up prompt, then complete automatically |
| 选项二说明 | 先把提示词发给这张卡片的会话；这一轮正常跑完就自动移入已完成。 | Send the prompt to this card's conversation first; the card moves to Done when that turn finishes normally. |
| 提示词标签 | 收尾提示词 | Wrap-up prompt |
| 提示词占位 | 例如：把这轮改动补进 CHANGELOG.md，写清改了什么、为什么，然后提交。 | e.g. Add this change to CHANGELOG.md, explain what changed and why, then commit. |
| 提示词帮助 | 会作为一条普通用户消息发进会话，不加前缀。建议写成能一次做完的指令。 | Sent as a normal user message, with no prefix. Write it as a single, self-contained instruction. |
| 失败说明 | 如果这一轮报错或被中止，卡片会回到待审核，不会标成已完成。 | If the turn fails or is aborted, the card returns to Review instead of being marked done. |
| 保存 | 保存 | Save |
| 已保存 | 已保存 | Saved |
| 校验 | 写一条提示词后再保存 | Write a prompt before saving |
| 超限 | 提示词最多 4000 字符 | Prompt is limited to 4000 characters |

**交互规则**：

- 选「什么都不做」时，提示词输入区收起，但**已保存的提示词不丢**；以后再选「发送提示词」会恢复。
- 选「发送提示词」但输入框为空：显示校验错误，**不允许保存这个模式**；列表里仍保留上一次已保存的设置。
- 提示词全为空白：按空处理。
- 提示词不解析变量、不解析斜杠命令；原样发送（仅 trim 首尾）。
- 提示词会明文写进本机的 `board.json`，不要在这里放 token / 密码。
- 选「发送提示词」时，完成按钮的 `title` / `aria-label` 要跟着变（按钮文字不变，仍是「✓ 完成」）：
  - 卡片：`标记完成，并先发送收尾提示词`；
  - 列表行：同上；
  - 会话标题栏：`发送收尾提示词，跑完后自动完成（fx-12）`。

### 5.3 保存与生效

- 没有「保存后重启」这一步：保存走 `POST /kanban-fx/settings`，Host 立刻更新内存里的设置并广播 `rev`，所有标签页同步。
- 保存方式：
  - 停手 **600ms** 自动保存一次（和新建待办的自动保存气质一致）；
  - 输入框失焦、点「← 返回」、切面板前补存一次；
  - 页脚保留一个「保存」按钮，给不信任自动保存的人一个明确出口；没有改动时置灰并显示「已保存 21:13」。
- 保存状态放在页脚，`role="status" aria-live="polite"`：
  - `自动保存已开启` / `有未保存的改动` / `保存中…` / `已保存 21:13` / `保存失败：…（重试）`。
- 保存失败**不丢草稿**：留在页面上报错，恢复后可重试。
- 校验不通过时：不发请求，状态显示「有未保存的改动」，并给出行内错误。
- 多标签页：另一个标签页改了设置，本页在**没有未保存改动**时静默同步；本页有草稿时先不动草稿，保存以最后一次写入为准（v1 接受 last-write-wins）。
- 生效时机：保存后**下一次**点「完成」生效；正在收尾中的卡片不受影响（它的提示词已经发出去了）。

### 5.4 点击「完成」之后（按时序）

**正常路径（mode = prompt）**：

1. 用户点「✓ 完成」（卡片 / 列表 / 会话标题栏）。
2. Host 校验卡片是 `review`；不是则 409（例如另一个标签页已经开跑）。
3. 解析会话 agent。会话已归档 / 找不到 → 直接 `doneAt = now`，返回 `completionResult = 'fallback-done'`。
4. 设置 `runningSince = now`、`lastRunStartedAt = now`、`doneAt = null`、`error = null`、`finishingSince = now`，广播一次。
5. 用 `agent.followup({ id: randomUUID(), role:'user', content:[{type:'text', text:prompt}], source:{kind:'user'} })` 投递。
6. 投递抛错（agent 忙 / 未知）：回滚 4 的字段，广播，返回 409，卡片留在待审核。
7. 成功后返回 `completionResult = 'sent'`，卡片 `status = running`、`finishing = true`。
8. `turn/start`：更新 `runningSince`，**保留** `finishingSince`。
9. `turn/end`：
   - reason 是 `error` → 清 `runningSince` / `finishingSince`，保留 `error`，落回待审核；
   - reason 是 `aborted` → 清 `runningSince` / `finishingSince`，落回待审核；
   - 其他（正常结束）→ `doneAt = event.time`，清 `runningSince` / `finishingSince`，落回已完成。

**入口差异**：

| 入口 | mode = none | mode = prompt |
|---|---|---|
| 看板卡片「✓ 完成」 | 立即完成；toast 带「撤销」 | 发提示词；卡片移到进行中（收尾中）；toast「已发送收尾提示词，跑完自动完成」，**不带撤销** |
| 列表行「完成」 | 同上 | 同上 |
| 会话标题栏「✓ 完成」 | 标完成并跳回看板（现有 notice，带撤销） | 发提示词后**仍跳回看板**；卡片落在进行中（收尾中）；看板提示「已发送收尾提示词，跑完自动完成」，不带撤销 |
| 已完成卡片「↩ 撤销」 | 回待审核 | 回待审核；**不会撤回已发出的消息** |

为什么仍然跳回看板：看板 / 列表上的「完成」本来就在看板上直接换列；会话标题栏的「完成」从 0.2.0 起就是「标完成并跳回看板」。prompt 模式只改变落点，不改变去向，三个入口都维持用户已经形成的预期。收尾是否跑起来、是否跑完，看板上的「收尾中」→「已完成」会如实反映；失败就回「待审核」并带报错，不会静默成功。

从会话标题栏跳回看板时，`pendingBoardNotice` 按 `completionResult` 分三种：

| `completionResult` | 看板 toast | 撤销 |
|---|---|---|
| `done` | 已把 fx-12 移到已完成 | 有 |
| `sent` | 已发送 fx-12 的收尾提示词，跑完自动完成 | 无（消息已发出，撤不回） |
| `fallback-done` | 会话不可用，已直接完成 fx-12（收尾提示词未发送） | 有 |

跳回时仍按卡片的工作区定位，和现在一样；`sent` 的卡片落在「进行中」列，状态显示「收尾中」。

### 5.5 状态与展示

**不新增第五列，不新增第五种状态**。`status` 仍只有 todo / running / review / done；「收尾中」是 `running` 上的一个派生文案：排序、筛选、计数、接口状态都不变，只改用户看到的字。

| 位置 | 普通进行中 | 收尾中 |
|---|---|---|
| 看板列 | 进行中 | 进行中（计数不变） |
| 看板卡片 | 计时 + 「运行中」 | 计时 + 「收尾中」；`title` 说明「收尾提示词正在跑，跑完自动完成」 |
| 列表状态 pill | 进行中 | **收尾中**（圆点沿用进行中；`title` / 读屏为「进行中 · 收尾」） |
| 列表用时 | 实时计时 | 实时计时（收尾这一轮的时长） |
| 会话标题栏 | `● 进行中` | `● 收尾中`（圆点沿用进行中；提示文案说明跑完自动完成） |
| 已完成卡片 | — | 正常已完成，不保留「收尾」痕迹 |
| 报错徽标 | 现有 | 收尾失败回待审核后显示「有报错」，和普通报错一致 |

视觉：

- 「收尾中」沿用现有状态标 / pill 的样式与 `--dsw-alias-*` token，不新增颜色；列表里它就是一个状态 pill 的文案变体，不是额外 chip。
- 卡片脚部的「运行中」在收尾时变成「收尾中」，**不要**只加一个需要悬停才能看到的点。
- 读屏：卡片 `aria-label` 补一句「收尾中」；列表 pill 的文本是「收尾中」，`title` 解释「进行中 · 收尾」；不能只靠颜色。

### 5.6 撤销与再完成

- 自动完成后，卡片和普通已完成完全一样，可以「↩ 撤销」回到待审核。
- 撤销只改卡片状态，**不会撤回**已经发进会话的收尾消息，也不会让 agent 停止。
- 撤销后再点「完成」：prompt 模式下会**再发一次**收尾提示词（视为用户主动重试）。文档和 UI 不额外警告——这是用户明确点的。
- 收尾进行中不提供「取消收尾」：消息已经投递，无法可靠撤回；卡片是 running，删除也会被现有规则挡住。

### 5.7 高级

高级区 v1 只做**只读信息 + 本地偏好重置**，不做破坏性操作。

| 分组 | 内容 | 说明 |
|---|---|---|
| 数据 | 数据目录、`board.json` 路径、存储版本、卡片总数（全部工作区） | 路径 / 版本来自 Host 的 `advanced`；总数按 `cards` 计；路径旁有「复制」 |
| 限制（只读） | 单张卡片正文字符上限、附件总大小上限 | 标注「在 `cordis.patch.yml` 中修改，重启后生效」，不在 UI 改 |
| 界面偏好（本机） | 当前默认视图（看板 / 列表）、列表排序 | 来自 localStorage；「恢复视图与排序默认值」只清 `dsh-kanban-fx.view` / `dsh-kanban-fx.sort`，不动工作区记忆、不动卡片数据 |
| 关于 | 插件版本（读 `package.json`）、数据格式版本、接口前缀 | 只读，方便报 issue 时贴 |

**为什么这些放高级**：它们是诊断 / 部署信息，不是日常设置；放主区会把唯一真正需要改的「完成之后」淹掉。

**为什么不在 UI 改上限 / 数据目录**：这些是 `cordis.patch.yml` 的部署配置。DSH 的 `configEditor` 修改普通字段会重启插件；本插件只依赖 node 内置模块与 `ctx` 服务，不为了一个字段引入 Schema 依赖，也就没有 `.volatile()` 的热更新字段。为了一个上限让看板重启、断 SSE、重读 `board.json`，不值得。v1 只读展示，保持「部署配置」和「用户设置」两套东西不混。

### 5.8 空态、错误、窄屏、无障碍

- **加载中**：设置页显示两块骨架，不闪「什么都不做」再跳成 prompt。
- **读取失败**：沿用看板错误条 + 「重试」；设置页正文显示「看板读取失败，设置暂时不可用」，保存按钮禁用。
- **保存失败**：行内错误 + 重试按钮；草稿保留；不自动关闭页面。
- **窄屏 < 700px**：单列；标签在控件上方；高级的「字段 / 值」两列改上下两行；页脚保存按钮全宽。
- **窄屏 < 430px**：顶栏齿轮只留图标；返回按钮只留 `←`，标题仍是「设置」。
- **深色**：只用 `--dsw-alias-*` token；自查要覆盖浅色 / 深色两套。
- **键盘**：Tab 顺序 = 返回 → 两个 radio → 提示词 → 保存 → 高级里的按钮；radio 用原生 `fieldset` / `legend` 或等价 `role="radiogroup"`；提示词有 `<label for>`、`aria-describedby`（帮助 + 错误）、超限时 `aria-invalid="true"`。
- **不依赖悬停**：收尾状态、报错原因、完成后的提示都要有可读文本，不能只放在 `title` 里。

## 6. 状态机与边界

### 6.1 卡片状态推导

```
status(card):
  finishingSince 非空          → running（finishing = true）
  runningSince 非空            → running
  没有 sessionId               → todo
  doneAt 非空                  → done
  否则                         → review
```

- `finishingSince` 是**独立字段**，不替代 `runningSince`；两者都在收尾期间非空。
- `viewOf` 增加派生字段 `finishing: Boolean(card.finishingSince)`；不把内部时间戳直接暴露给 UI。
- 收尾中的卡片仍受现有「正在运行不能删除 / 不能改内容」保护。

### 6.2 状态迁移表

| 当前 | 事件 | 条件 | 结果 | 备注 |
|---|---|---|---|---|
| review | 点完成 | mode = none | done | 现状 |
| review | 点完成 | mode = prompt，会话可用 | running + finishing | 先发提示词 |
| review | 点完成 | mode = prompt，会话已归档 / 不存在 | done | `fallback-done` + 警告 |
| review | 点完成 | mode = prompt，agent 忙 / 解析失败 | review | 409，卡片不动 |
| running + finishing | turn/end 正常 | — | done | 自动完成 |
| running + finishing | turn/end error | — | review | 保留 error |
| running + finishing | turn/end aborted | — | review | 不标完成 |
| running + finishing | agent 空闲超过 10s / 重启后已停 | — | review | `error = '收尾没有跑起来，请再点一次完成'` |
| done | 撤销 | — | review | 不撤回消息 |
| done | 会话里继续说话 | — | running | 现有规则；跑完回 review |
| review / done | 用户直接改设置 | — | 不变 | 只影响下一次点完成 |

### 6.3 失败与兜底

| 情况 | 行为 | 用户看到 |
|---|---|---|
| 会话已归档 / 已删除 | 直接完成，`completionResult = 'fallback-done'`，`completionWarning = 'session-archived'` / `'session-missing'` | toast「会话已归档 / 不可用，已直接标记完成（收尾提示词未发送）」 |
| `agent.followup` 抛错（忙 / 未知） | 回滚 running / finishing，卡片留 review，409 | 现有错误 toast；卡片不动 |
| 收尾轮报错 | 回 review，保留 error | 卡片「有报错」徽标；可再点完成重试 |
| 收尾轮被中止 | 回 review，error 清空 | 卡片回待审核 |
| Host 在收尾中重启，turn 已结束 | 启动 3s 后的 reconcile：agent 已不在 running → 过了 10s 宽限后清 finishing / running，回 review（最坏等下一次 reconcile，约 30s） | 不自动完成；卡片带「收尾没有跑起来」提示，用户再点完成 |
| Host 重启时 turn 仍在跑 | 保留 finishing；`session/event` 恢复后照常自动完成 | 进行中（收尾中） |
| 收尾期间用户又在会话里说话 | 不取消收尾；自动完成落在**下一次** `turn/end` | 已知限制，见 6.6 |
| 收尾期间用户改设置 / 关浏览器 | 已发出的提示词不受影响；卡片状态由 Host 继续维护 | 无额外提示 |
| 提示词被保存为空（脏数据） | 完成时按 none 处理，立即完成 | 不额外弹错；设置页会阻止保存这种状态 |

### 6.4 并发与多端

- 两个标签页同时点「完成」：第一个把卡片置为 running；第二个收到 409，卡片不动，前端重新读板后按钮已消失。
- 两个标签页同时保存设置：后写覆盖先写；各自收到新 `rev` 后重读。设置页在没有本地草稿时静默更新；有草稿时不覆盖输入框。
- 收尾中在另一个标签页点「撤销」：卡片是 running，没有「撤销」入口；不会出现撤销成功的假象。
- 收尾中删除卡片：Host 仍然拒绝（`runningSince` 非空）。

### 6.5 Host 重启

- `board.json` 持久化 `finishingSince`，重启后卡片仍显示「收尾中」。
- 重启后如果 agent 已停：**不猜成功**，回待审核，让用户重新点完成。宁可多一次点击，也不要把失败标成完成。
- 重启后如果 agent 仍在跑：保留收尾态，等 `turn/end`。

### 6.6 已知限制（写进 README，不写进 UI 噪音）

1. 收尾期间用户在会话里补话，自动完成会落在补话那一轮的结束，而不是收尾轮。v1 不试图区分「哪条消息是收尾」。
2. 收尾提示词是全局一条，不能引用具体卡片编号；需要卡片信息时，建议写成依赖会话上下文的指令（如「把这轮改动……」）。模板变量见第 12 节。
3. 撤销完成不会撤回收尾消息。
4. 保存设置后，正在收尾中的卡片继续按旧提示词执行；新设置只影响下一次点击。
5. 设置按数据目录生效（`$DSH_HOME/dsh-kanban-fx`）；换 profile / 换数据目录不会带过去。

## 7. 数据与接口

### 7.1 `board.json`

新增顶层字段，旧文件没有就取默认：

```json
{
  "version": 2,
  "rev": 7,
  "nextSeq": 12,
  "lastWorkspaceId": "ws-1",
  "settings": {
    "completion": {
      "mode": "none",
      "prompt": ""
    }
  },
  "cards": {
    "card-…": {
      "…": "现有字段",
      "finishingSince": null
    }
  }
}
```

字段定义：

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `settings.completion.mode` | `'none' \| 'prompt'` | `'none'` | 点完成后做什么 |
| `settings.completion.prompt` | string | `''` | 收尾提示词，trim 后 ≤ 4000 字符 |
| `card.finishingSince` | number \| null | `null` | 收尾轮开始时间；非空即收尾中 |

### 7.2 版本与迁移（重要）

- **不要**为了加 `settings` 把 `STORE_VERSION` 从 2 升到 3。
- 现有 `loadStore` 用 `fromVersion < STORE_VERSION` 判断「v1 自动标题」，如果升到 3，v2 卡片会被误判成 v1，用户手写、但恰好等于正文派生的标题会被清成空串（自动派生），属于静默数据损坏。
- 正确做法：保持 `version: 2`，把 `settings` 当**可选新增字段**读取；老文件没有就补默认值，写入时带上。
- 如果未来确实要升 3，迁移条件必须先改成 `fromVersion < 2`，再用单独的 2 → 3 迁移处理新字段。
- 读取时要 sanitize：mode 只接受白名单，prompt 截到 4000，非法值回落默认；不能因为脏设置让插件启动失败。

### 7.3 `GET /kanban-fx/board` 增补

```json
{
  "ok": true,
  "rev": 7,
  "serverNow": 1760000000000,
  "cards": ["…"],
  "workspaces": ["…"],
  "defaultWorkspaceId": "ws-1",
  "settings": {
    "completion": { "mode": "prompt", "prompt": "把这轮改动补进 CHANGELOG.md……" }
  },
  "advanced": {
    "version": "0.5.0",
    "dataDir": "/Users/…/.dsh/dsh-kanban-fx",
    "storeFile": "/Users/…/.dsh/dsh-kanban-fx/board.json",
    "storeVersion": 2,
    "limits": {
      "maxBodyChars": 200000,
      "maxCardAttachmentBytes": 25165824
    }
  }
}
```

- `advanced` 是只读运行信息，不含附件字节，不含环境变量。
- 不新增 `GET /settings`：设置跟随看板一起读，省一个请求，也天然吃到 SSE 的 `rev`。
- 卡片 `viewOf` 增加 `finishing: boolean`。
- `GET /kanban-fx/card` 返回的卡片额外附带 `completionMode`，供会话标题栏 tooltip 判断「完成」是立即完成还是先发提示词；看板卡片从 `settings` 读，不重复带。

### 7.4 `POST /kanban-fx/settings`

请求（整体替换，未知字段忽略，便于以后加设置）：

```json
{
  "settings": {
    "completion": {
      "mode": "prompt",
      "prompt": "把这轮改动补进 CHANGELOG.md，写清改了什么、为什么，然后提交。"
    }
  }
}
```

响应：与 `GET /board` 相同的完整看板 payload（含 `settings` / `advanced` / `rev`）；设置保存不涉及具体卡片，不带 `card` 字段。

规则：

- 与现有 `/kanban-fx/*` 一样走 `connection.requestRejection` 的 Host / Origin / 登录校验。
- `mode` 不在白名单 → 400；`mode = prompt` 且 trim 后为空 → 400；prompt 超 4000 → 400。
- `mode = none` 时允许保存空 prompt；非空 prompt 也保留，方便再启用。
- 保存后立刻 `saveNow()` 落盘，`rev += 1`、广播 `reason: 'settings'`，所有客户端静默重读。
- 不重启插件，不重载 `board.json`，不动正在跑的卡片。

### 7.5 `POST /kanban-fx/card` 的 `done` 增补

`done` 响应在现有字段外增加：

| 字段 | 值 | 含义 |
|---|---|---|
| `completionResult` | `'done'` | 直接完成（mode = none） |
| | `'sent'` | 收尾提示词已发送，卡片正在收尾 |
| | `'fallback-done'` | 想发但会话不可用，已直接完成 |
| `completionWarning` | `'session-archived'` \| `'session-missing'` \| null | 仅 `fallback-done` 时出现，客户端据此本地化提示 |

- `card.status` / `card.finishing` 仍然返回，客户端不靠猜。
- 409 的错误信息保持现有风格；`done` 在 running 卡片上仍然拒绝。
- 收尾提示词投递后不调用 `nameSession`，不 flush 也无妨（`turn/start` 会落盘；需要更强一致性时可复用 `runCard` 的 flush，失败只打日志）。

### 7.6 校验与限额

| 项 | 值 | 备注 |
|---|---|---|
| prompt 长度 | 4000 字符，统一按 `String.length` 计，与现有 `textOf` 一致 | 前后端同一规则 |
| 保存请求体 | 现有 40MB 上限足够；不需要单独限制 |  |
| 轮询 / SSE | 不变 | 设置保存也走 `rev` |
| 权限 | 现有 Host / Origin / 登录校验 | 不新增 |

## 8. 实现落点

### Host（`index.js`）

- `loadStore`：读 `parsed.settings`，sanitize；卡片补 `finishingSince`。
- 现在 `normalizeSettings(config)` 这个名字容易和用户设置混淆：建议把插件配置改叫 `configSettings` / `normalizeConfig`，用户设置叫 `userSettings` / `sanitizeUserSettings`。
- `viewOf`：加 `finishing`。
- `boardPayload`：加 `settings`、`advanced`（数据路径、版本、上限）。
- `markDone`：改为 async；mode 分支；`resolveAgent`；投递；回滚；`completionResult`。
- `handle` 的 `done` 分支要改成 `await markDone(...)`（现在是同步调用）。
- `turn/start`：不要清 `finishingSince`。
- `turn/end`：finishing 时按 reason 决定 done / review。
- `reconcile`：finishing 的 10s 宽限和「不猜成功」兜底。
- `handle`：新增 `POST /kanban-fx/settings`；`done` 响应加 `completionResult`。
- `removeCard` / `updateCard` 不需要改：running 期间本来就被挡。

### Client（`client.js`）

- `Panel`：新增 `settingsOpen` 状态（不持久化）；顶栏齿轮；内容区分支。
- 新增 `SettingsPage`：radio + textarea + 保存状态 + 高级区；从 `board.settings` / `board.advanced` 取数；保存用独立的 `postSettings`，复用同一套 `applyBoard`。
- `applyBoard`：保留 `settings` / `advanced`。
- `markDone`（看板 / 列表）：按 `completionResult` 决定 toast 文案和是否给撤销。
- 卡片 / 列表：`finishing` 标识。
- `HeaderCardState`：无论 `completionResult` 是 `done` / `sent` / `fallback-done`，成功后都照旧 `openBoard` 跳回看板；区别只在交接提示（`sent` 不带撤销）。状态标在 `card.finishing` 时显示「收尾中」；状态推导不能只看会话的 `running`，也要看 `card.status === 'running'`（否则提示词刚发出、会话还没翻成 running 的那一拍会闪回「待审核 + 完成」）；跑完由 `running true → false` 的 effect 重新读卡。
- `IconGear`、`IconBack`（或文字箭头）；样式全部 `fxk-` 前缀，只用 token。
- 高级区「复制」复用现有 `copyText`；「恢复默认」只清两个 localStorage key。

## 9. 验收标准

按顺序全部通过才算完成：

| # | 场景 | 期望 |
|---|---|---|
| A1 | 全新安装 / 旧 `board.json` 没有 `settings` | 设置页两个选项默认「什么都不做」；点完成行为与 0.4.0 完全一致（立即完成、toast 带撤销） |

| A4 | 收尾轮正常结束 | 卡片自动进入已完成；会话标题栏变「已完成」；不需要再点一次 |

| A6 | 会话标题栏点完成（prompt 模式） | **仍跳回看板**；看板 toast 说「已发送收尾提示词，跑完自动完成」；卡片在进行中带「收尾中」；跑完自动「已完成」 |
| A7 | 会话已归档后点完成 | 卡片直接已完成；toast 说明「收尾提示词未发送」；不报 500 |

| A9 | 连续点两次完成 | 第二次 409 / 按钮已不可点；会话里只有一条收尾消息 |
| A10 | 自动完成后点撤销 | 回待审核；收尾消息仍在会话里；再点完成会再发一次 |

| A12 | 高级区 | 数据目录 / 版本 / 上限与实际一致；复制可用；「恢复默认」只改视图与排序，卡片数据不变 |
| A13 | 窄屏 / 深色 / 键盘 | 430px 下可用；深色 token 正常；Tab 顺序正确；radio 可键盘切换；错误可被读屏读到 |

## 10. 风险与取舍

| 风险 | 影响 | 缓解 |
|---|---|---|
| 「已完成」不再完全等于用户判断 | 用户可能没意识到卡片是自动完成的 | 默认关闭；收尾中醒目标识；toast 明说；失败不自动完成；撤销保留 |
| 点完「完成」却落在进行中 | 用户以为按钮没生效，尤其是从会话标题栏跳回来时 | 看板 toast 明确说「已发送收尾提示词，跑完自动完成」；卡片带「收尾中」；失败回待审核并带报错；按钮 tooltip 在 prompt 模式下改文案 |
| 自动注入一条用户消息 | 用户忘了自己开过设置，觉得 agent 突然说话 | 设置页显式说明；按钮 tooltip 变文案；首次启用后第一次点击的 toast 说明 |
| 收尾提示词写得像对话开场 | agent 反问，卡片却已自动完成 | 帮助文案要求「写成能一次做完的指令」；失败 / 反问由用户撤销或继续 |
| 收尾期间用户插话 | 自动完成落在补话轮结束 | 6.6 已知限制；v1 不识别消息来源，保持简单 |
| Host 重启在收尾中途 | 可能多一次点击 | 安全优先：回待审核，不猜成功 |
| 全局一条提示词会过时 | 不同任务的收尾需求不同 | v1 接受；后续可做每卡片 / 每工作区，schema 已按对象留扩展位 |
| 多标签页同时编辑 | 后写覆盖 | last-write-wins；保存响应回全量设置；无草稿时静默同步 |
| 误以为「撤销」能撤回消息 | 用户预期落差 | 撤销 toast 只说「回到待审核」；README 写清楚 |
